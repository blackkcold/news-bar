# 深度研究报告弹窗：单栏阅读器升级规格

- 状态：已落版，待产品确认；未实施。
- 基线：`release/v3.6.1`，`2c86f4f`，2026-11-25 源码复核。
- 上位设计：[研究报告阅读器](2026-11-23-research-report-reader-design.zh-CN.md)、[研究阅读与通知](2026-11-18-research-reading-notifications-v1.zh-CN.md)。
- 适用范围：统一研究报告浮窗，包括深度研究和使用同一弹窗的其他报告；不是 Dashboard 的 AI 简报。

## 1. 目标、非目标与方案选择

读者从新闻、通知或搜索打开弹窗时，第一眼要能确认「是哪份报告、得出了什么结论、有何关键限制」，再按需追查时间线和原文。看证据时应能回到原处，而不必把弹窗当成研究管理工作台。

| 方案 | 优点 | 取舍 |
|---|---|---|
| 仅压缩现有头部 | 改动最小 | 不解决长行、重复导航、旧来源和局限不可见 |
| **单栏阅读器，复用共享正文** | 精简首屏，保留阅读与查证路径 | 需要弹窗专属呈现配置，以及缺字段用例 |
| 将工作台双栏搬进弹窗 | 比较版本、管理来源更方便 | 620pt 下挤占正文，且扩大范围 |

**非目标：**不改研究任务、提示词、报告 JSON／`BurstResearch`、通知上限、已读触发或所有入口的路由语义；不增加文件导出、完整历史列表、开始／取消／重试任务，不替换 AppKit 面板，也不改现有「复制 Markdown」格式。不会为补显示而重新生成或改写已有报告。

## 2. 基线事实与待验证项

| 类型 | 结论 |
|---|---|
| 已核实 | `AppDelegate` 创建 760×760 的非模态 `NSPanel`，最小内容 620×560；弹窗与工作台共用 `ResearchReportReader`。 |
| 已核实 | 目录与章节头重复编号；滚动正文目前无最大行宽。`reload` 会加载版本数组，但普通打开没有保留可供头部显示的版本序号。 |
| 已核实 | 有新报告时现有逻辑会保留旧报告供继续阅读；主动切换触发正文 digest 变化时回到结论。同目标在窗口仍开时的重复打开，不等同于关闭后再开。 |
| 已核实 | `verification == nil` 可能让既有 `limitations` 不可见；来源章以结构化 `evidence` 判断，`report.sources` 单独存在时可能既无入口，又被误提示没有来源。 |
| 待实测 | 字号、行宽、首屏面积，以及 VoiceOver 内容、焦点和主题在真实 `NSPanel` 上的表现。现有 reader 渲染快照不能替代面板验收。 |

## 3. 线框与布局规格

图中内容为示例，不是实机截图；窗口上的控件使用原生 SwiftUI／AppKit，而不是照搬字符图。

```text
阅读首屏（默认窗口）                         窄窗口 / 引用打开
╭── 研究报告 ───────────────────────────╮  ╭── 研究报告 ──────────────────╮
│ V3 · 11 月 25 日       研究中心  ···  │  │ 历史版 V2 · 11 月 24 日   ··· │
│ 某行业新规：何时落地？                │  │ 某行业新规：何时落地？        │
│ 结论 ━━━  时间线    核验    来源      │  │ 结论   时间线 ━━━  核验   来源 │
├───────────────────────────────────────┤  ├───────────────────────────────┤
│       核心结论                        │  │ 11.22 征求意见稿发布 [E1]     │
│       正式规则尚未发布。适用范围……    │  │             ╭── 来源 E1 ────╮ │
│       仍待确认：过渡期 → 核验         │  │             │ 标题、域名     │ │
│                                       │  │             │ 引文与状态     │ │
│       时间线                          │  │             │ 打开原文       │ │
│       11.22 征求意见稿发布 [E1]       │  │             ╰───────────────╯ │
╰───────────────────────────────────────╯  ╰───────────────────────────────╯

尚无报告                                  旧报告缺结构化证据
╭── 研究报告 ───────────────────────╮     ╭── 正文后半段 ─────────────────╮
│ 研究中 · 尚无可读报告    研究中心 │     │ 核验与局限                    │
│ 正在读取来源                      │     │ 暂无逐条核验。报告只覆盖公开… │
│ [ 已知进度，或不确定进度指示 ]    │     │ 来源                          │
│ 关闭此窗口不会取消研究。          │     │ example.org · 旧版链接／无引文│
╰───────────────────────────────────╯     ╰───────────────────────────────╯
```

| 区域 | 布局和优先级 |
|---|---|
| 窗口 | 保留尺寸、原生标题栏与缩放行为。窗口变宽时只扩大留白，不拉长正文行；沿用应用浅色／深色／复古主题，正文背景以可读性优先。 |
| 头部 | 标题优先，标题允许换行；版本／日期是次级信息。窄宽时先收起次要动作到更多菜单，不挤掉标题或把按钮改成无文字含义的图标。更多菜单保留复制 Markdown。 |
| 目录 | 沿用同一组原生按钮和章节 ID。不显示编号和计数；当前章有文本或形状变化，不仅靠颜色。无内容的章不出现；存在已知局限或旧链接时不能仅因缺 `verification` 或 `evidence` 而隐藏对应入口。 |
| 正文 | 单一主滚动区域；建议正文净宽不超过约 640pt、左右保留至少 18pt 余量，正文初始字号 15–16pt，中文长文与英文长链接都要验收。正文摘要可完整滚动，不按行数截断。正文与当前定位区域不套第二层滚动。 |
| 次要状态 | 已有可读报告时，进度和新版入口最多占一条紧凑状态区。两种信息同时存在时，新版入口优先，旧版日期保留在头部。没有报告时才在主区域显示进度或空态。 |

默认尺寸用短摘要样例验收：不用滚动即可读完结论并看到时间线入口（有时间线时）。最小尺寸和长摘要不承诺时间线一定在首屏，优先保全文字与操作。换行、无横向溢出、阅读列宽和可达性优先于像素对齐。

## 4. 内容、状态和交互契约

### 4.1 展示数据（不改变存储格式）

| 字段或条件 | 呈现规则 |
|---|---|
| 标题 | 沿用弹窗现有事件标题／研究主题优先级。打开新目标时不得把旧目标的标题和报告混用。 |
| 版本 | 使用与实际显示报告相匹配的版本记录和序号；明确为历史入口时标记「历史版」。无法确认序号则只显示已知日期，不猜 `V#`；序号 `0` 不显示为 `V0`。 |
| 日期／任务状态 | 报告日期来自显示的报告版本；研究运行状态单独表达，只描述当前任务。不得把最新失败或运行中的状态标给历史报告。 |
| 结论与注意事项 | 复用原有摘要和概览。已有「仍待确认」信息可在结论处给出短提示与锚点；完整限制放到核验章，只显示一次。没有限制数据不等于没有局限，不给出额外承诺。 |
| 时间线 | 沿用已有条目和原有顺序、日期表达及证据引用；无有效节点时不提供死锚点，不用生成时间充当事件时间。 |
| 逐条核验 | 已有核验按证据显示；缺核验时可提示「暂无逐条核验」，但不影响局限展示，也不为此重跑研究。 |
| 来源 | 保持 `evidence` 的编号与引用目标。`sources` 中可打开且未被结构化证据覆盖的 URL，legacy 报告（`reportVersion == 0`）标为「旧版链接」，其他报告标为「其他来源链接」，都注明无引文。禁止虚构标题、日期或核验状态。 |
| 复制 | 现有 Markdown 内容保持不变，复制的是正在显示的版本。复制内容不以界面可见字段为限：现有界面在 `verification == nil` 时可能不显示 `limitations`，但 `WorkspaceReportBody` 的 Markdown 仍输出非空的 `limitations`。可补原生确认反馈；界面不称「所见即所得导出」。 |

### 4.2 打开、更新、滚动与键盘

1. **入口不变，目标身份明确。** 新闻角标、Dashboard、通知、搜索仍收敛到 `openTransientResearch`。目标键由带类型的 `recordID`（优先）或 `eventID`、请求的 `versionID` 和 `compareFromVersionID` 构成。已解析到同一记录时，仅更新 fallback 标题或链接不重建阅读器；若记录和事件都缺失，则沿用 URL 兜底识别，不把不同兜底文章合并。同目标再次打开且窗口仍在时保留位置；切换目标、明确切换版本或关闭后重开从结论开始，首版不持久化位置。
2. **初次加载。** 正在请求数据与确实无报告要有不同反馈。没有报告但已有事件摘要时，可保留并清楚标注「事件信息，非研究报告」。明确失败时显示简短状态与研究中心入口，不把未开始或未匹配当成失败。
3. **更新。** 只更新运行进度、状态或提示时，内容身份不变、正文不重置；新版加载失败不得清掉旧报告。点击「查看新版」后才替换显示版本，回到新版结论，即使两个版本正文相同；显式历史入口不自动跟随。优先复用现有手动切换及版本比较路径，弹窗保留独立的显示版本身份，不修改工作台的滚动重置语义。
4. **跳转。** 目录与结论中的「查看核验」共用章节 ID；跳转后的标题不得被固定界面遮住。普通滚动只更新选中状态，不强抢键盘焦点；由键盘主动跳章节时提供清楚的焦点或读屏定位。
5. **引用。** 点击或键盘激活引文时显示现有证据卡；读屏可辨认引用编号、来源和展开状态。关闭引用卡后焦点回到引用按钮，正文位移不变；Esc 先关闭打开的引用卡，再按窗口现有行为关闭弹窗。
6. **焦点。** 头部动作 → 目录 → 正文可互动项；使用原生 `Button`／菜单，不用独占手势代替按钮。不可用章节不进入 Tab 顺序；选中章不能仅用颜色区分。首版不新增 `⌘1…⌘4` 等全局快捷键。

### 4.3 章节门控与 URL 去重

- **弹窗章节规则：**结论始终可达；时间线需要可展示节点；核验在有核验、证据或非空局限时可达，缺核验分支也展示原有局限；来源在有结构化证据或可展示补充链接时可达。工作台仍使用原有门控，来源栏接管时遵守 `showsSourceSection`。
- **补充来源算法：**对原始 `sources` 和用于匹配的证据 URL 做统一 canonical 比较，复用 `ContentIdentity.canonicalURL`；补充 URL 先通过 `ReaderNavigationPolicy.allowedURL`，再按 canonical 键排除证据中已有项、按原 `sources` 首次出现顺序去重。打开时仍用 `openEvidenceURL`，不拿 canonical 比较值替换实际目标，不因补充链接重新编号证据。

## 5. 工程拆分、边界和回退

| 工作包 | 修改面（计划） | 完成条件 |
|---|---|---|
| A1 · 弹窗外壳 | `TransientResearchReportView`／Model、`AppDelegate` 的面板宿主 | 头部、状态、主题、确认反馈可独立启用；不碰工作台窗口和报告载荷。 |
| A2 · 弹窗阅读呈现 | `ResearchReportReader`／章节组件，使用一个带默认值的呈现配置 | 配置承载列宽、正文字号、导航／标题编号和计数、章节可用性规则。工作台不传新配置时，其章节结构、选中指示、默认展开和既有渲染基线不变；不引入 `isPopup` 分支散落在各章节中。 |
| A3 · 验收 | 复用阅读器渲染矩阵；新增弹窗状态及旧报告 fixture；实机键盘与窗口验收 | 能区分视图结构断言和需要实际面板的行为；工作台窄／宽布局及版本切换均复核。 |

保持章节 ID、顺序、滚动坐标系、引用目标和工作台 `showsSourceSection` 契约；不另做一套目录／滚动观察器。可读状态与载荷兼容优先，未确认的版本信息用文案降级。A1 与 A2 分开评审；若共享渲染有回归，可撤回 A2 的弹窗配置并保留 A1，不涉及数据库或报告数据回退。若只交付 A1，不能宣称完成本规格，因为旧来源和局限仍是发布验收项。

## 6. 验收矩阵

| ID | 条件／操作 | 通过标准 |
|---|---|---|
| R01 | 默认 760×760 的短摘要；620×560 的长摘要；窗口放大及放大文字 | 短摘要首屏可读，长摘要不裁剪、无横向滚动、无嵌套主滚动；放大窗口不拉长正文。 |
| R02 | 浅色、深色、复古主题；系统与 App 外观偏好不一致 | 使用 App 现有解析结果，标题、正文、次要文本及焦点在真实面板均可辨认。 |
| R03 | 通知打开历史版；另一个任务仍在运行或失败 | 日期和 `V#` 属于显示版本，当前任务状态不会污染历史版；无可靠序号时不伪造。 |
| R04 | 滚到核验；更新进度；新版就绪；点击新版 | 前两步不换报告、不跳位；主动切换到新版结论；旧版链接打开仍得到对应版本。 |
| R05 | `limitations` 有、`verification` 与 `evidence` 均无；另测有 `evidence` 的情况 | 即使没有证据也有核验／局限入口；原有局限可读，状态不显示成已核验，限制正文不重复。 |
| R06 | legacy 和现代报告的 `sources`；另测与 `evidence` 重复、跟踪参数变体及不可打开链接 | 标签分别正确；按首次出现顺序呈现预期条数；安全链接可打开、不重复、非法目标无可点入口、不改原引用编号。 |
| R07 | 只用键盘和 VoiceOver 操作目录、E1 和窗口关闭 | 状态可读、焦点可见、章节定位正确、关卡片后返回原位。 |
| R08 | 运行中无报告、失败无报告、仅事件信息 | 文案区分准确，无错误完成状态；关闭面板不取消任务，研究中心入口保留。 |
| R09 | 同一记录且 fallback 文案／URL 不同；显式切另一版本；关后重开；不同目标异步交错 | 同目标窗口仍开时保位；显式改版本、重开或新目标到结论；过时响应不覆盖当前目标。 |
| R10 | 工作台来源栏开启／关闭；历史切换；弹窗复制 | 工作台导航、来源栏、默认折叠和版本切换不变；复制仍遵守原 Markdown 契约。 |

未来实现验证入口：`swift test --filter ResearchReportReaderRenderingTests`、`swift test --filter ResearchReportMetricsTests`，再运行 `swift test`；窗口、焦点、滚动和主题需实机验收。以上命令在本次方案落版中不运行。
