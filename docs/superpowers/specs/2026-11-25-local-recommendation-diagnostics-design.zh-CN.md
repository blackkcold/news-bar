# 本地个性化推荐：诊断采集、Agent 访问与排序升级规格

- 状态：已落版，待产品确认；未实施。
- 基线：`release/v3.6.1`，`2c86f4f`，2026-11-25 源码复核。
- 适用范围：NewsBar Dashboard「为你推荐」的本机个性化排序，不涉及地理位置、RSS 推荐源目录、菜单栏、通知、AI 简报或深研候选。
- 已有设计：[推荐解释](2026-10-26-recommendation-explainer-design.md)、[推荐原理与我的兴趣](../../recommendations-explained.zh-CN.md)。

## 1. 目标与设计决策

目前知道「看见」和「读过」的部分信息，但不能可靠判断某次阅读来自哪次推荐、点击失败了还是没有兴趣、以及排序变化有没有提高阅读质量。本方案先建立可解释的本机诊断，再验证一个明确的排序假设。

| 决策 | 采用 | 不采用及原因 |
|---|---|---|
| 诊断与画像 | 复用触发点，独立采集和存储 | 不让点击、失败、放弃或试验标记自动变成画像证据；不拿现有兴趣库当导出库 |
| Agent 出口 | 默认关闭、短时授权、运行中 App 返回固定汇总 | 不沿用通用 `outbox` 落盘；不开放数据库、原始事件或任意查询 |
| 排序第一步 | v4 不动，先用三态诊断和影子排序验证单一假设 | 不先调一组全局权重，不引入向量、地理信息或云端训练 |
| 试验范围 | Dashboard 展示路径单独试验 | 不改通知、研究候选或 AI 简报的排序及缓存键 |

**成功条件：**诊断关闭时产品行为无变化；开启后可区分曝光、点击、加载和阅读；Agent 能在授权期间读取可靠、解释得清分母且低泄露的汇总；没有充分证据时保持 v4。

## 2. 已有实现与真实缺口

| 环节 | 已核实的现状 | 本次结论 |
|---|---|---|
| 候选与排序 | 活跃条目与近 24 小时内容经过事件折叠，交给 `RecommendationEngine`。v4 已用画像置信度混合公共基线与个人分，并含硬屏蔽、去重、多样性和公共槽位。 | 候选口径、原榜顺序和现有冷启动逻辑先保持。 |
| 曝光 | 合格曝光要求前台、可见、未遮挡及连续可见门槛；现有去重跨度取仪表盘窗口存续期与 30 天中的较短者，因为 `LocalInterest.prune` 会裁掉超过 30 天的事件。 | 不追踪所有渲染或滚动；另定义诊断会话，不改变原曝光。 |
| 点击与阅读 | 点击时没有独立意图事件；成功加载后才有 `opened`。加载前关闭可能留 `.unknown` 会话；失败回调可能重复。 | 新诊断必须在点击时建立尝试，使用真实生命周期结算，不能由旧记录推断。 |
| 位次 | 事件 `position` 是 0 基快照下标；瀑布流实际摆放不按名次线性排列。 | 只汇总算法名次，首期不估计视觉位置效应。 |
| 分数 | 无标签时兴趣项不进入分母；有标签但未命中时该项以 0 计入分母。一些无标签内容共享 `unknown` 多样性桶。 | 这是可验证的规则差异，不等于已证实的体验缺陷；首个候选只检验分母差异。 |
| Agent | 通用命令写入 `outbox` 的结果没有回收路径（七天归档清理不覆盖，CLI 读取后也不删除），`quarantine` 只被创建和清理，全仓没有写入方。通用 Agent 设置不是推荐数据的单独授权。 | 不将诊断结果放进通用文件队列；不依赖回收文件来实现撤权。 |

## 3. 数据采集与关联

```text
推荐快照 ──→ 卡片满足现有合格曝光条件 ──→ exposureID
                 │                          │
实际点击的卡片 ──┴──→ clickIntent + attemptID ──→ firstOpenResult
                                   │                 │
                                   └──→ 有效阅读 / 深读（只在成功打开后）

独立许可门 → 本机有界诊断记录 → 聚合层 → App 设置页
                                     └──→ 单独短时授权 → Agent 只读汇总
```

### 3.1 生命周期与 ID

1. **诊断会话 `diagnosticSessionID`。** 仪表盘显示且允许采集时惰性创建；关闭仪表盘、越过本地日界、采集许可代次变化时结束。跨午夜在下一次合格曝光或用户动作时切换，不作后台心跳。未来若开展试验，变体时间块切换也结束本会话，并让新块重新通过曝光判定。原 `feedSessionID` 和学习侧去重不变。
2. **曝光 `exposureID`。** `(诊断许可代次, diagnosticSessionID, contentKey)` 只保留首次合格记录；保存当次快照和名次。滚动、重绘、过滤或任意重排不单独创造曝光；跨会话可重新满足门槛。不是合格曝光的渲染项既不落单条事件，也不计作「没兴趣」。
3. **点击 `attemptID`。** 推荐卡片交给路由时建立一次尝试，把实际点击卡片的会话、快照、名次和可匹配曝光传给生命周期；重复的回调不能创建第二次尝试。只有同一诊断许可代次、诊断会话、内容和展示变体，且曝光早于点击、相隔不超过 **30 分钟**，才允许匹配。阅读会触发快照重建，因此快照 ID 不作硬匹配键：同快照标 `same_snapshot`，同会话重排后匹配原曝光标 `after_rerank`。曝光指标仍使用曝光当时的变体和名次；点击质量使用点击当时的名次，不能把旧曝光算作新位置的曝光。过快点击、跨会话／变体、上下文丢失或超窗均为未归因，不补造曝光。
4. **阅读生命周期。** `opened` 采用现有成功归因口径，不用 WebView 单独一个技术回调代表成功。加载前关闭按实际状态产生独立结果，不能用 `.unknown` 或停留秒数反推。失去正确文章归因后，不把后面浏览归到原内容。每次尝试的后续阅读观察窗建议 **30 分钟**；未收到结果的中断尝试保留为未结算，不伪造失败。
5. **隐私切换。** 采集许可改变、清空、隐私阅读或暂停时废弃待写缓冲，并通过代次阻止旧事件在恢复后补写。Agent 授权代次单独管理：撤销读取授权不会取消本机诊断。日期和时窗是本规格默认设定，日界测试要覆盖系统时区变化；不把时区或设备标识输出给 Agent。

### 3.2 事件字典

| 事件 | 触发与幂等 | 诊断值 | 画像副作用 |
|---|---|---|---|
| `qualified_exposure` | 现有前台、未遮挡等条件下，卡片可见 ≥50% 且连续 ≥1 秒；会话内内容首次 | `exposureID`、算法名次、置信度桶、标签／命中状态 | 无；原学习事件不变 |
| `click_intent` | 进入推荐卡片打开路径时一次 | `attemptID`、实际点击名次、可空 `exposureID` | 无 |
| `first_open_result` | 每个尝试只保留一个首次结算结果 | `opened`／`failed`／`blocked`／`abandoned_before_load`；若已成功打开，后续跳转或错误不回写首次结果 | 无 |
| `read_milestone` | 已成功打开且仍有文章归因；每个尝试每级至多一条 | `engaged`：累计有效前台阅读时间 ≥15 秒，不要求站点适配；`qualified`／`deep`：仅在已有适配器能产生原阅读信号时作为辅助里程碑。深读不重复相加。 | 只复用计时与状态，不新增或强化原画像信号 |
| `explicit_feedback` | 收到明确的反馈动作；同一动作回调只计一次。与同一展示上下文精确匹配时才归入曝光漏斗 | 限定动作枚举，不含词、来源名或反馈文本；撤销作为独立类型，不把去掉的规则当作仍启用 | 原反馈规则沿用现状，诊断不另写规则 |

字段白名单：

| 字段 | 范围与用途 |
|---|---|
| `schemaVersion`、`kind`、`occurredAt` | 独立诊断 schema；本地仅为排序、裁剪和时窗匹配保留必要时间精度。不是兴趣库、全局策略或 Agent 信封版本。 |
| `diagnosticSessionID`、`snapshotID`、`contentKey` | App 内关联；内容键使用本机诊断作用域的不透明值，不保存 URL 或其可公开枚举的裸散列，不跨设备复用。 |
| `exposureID?`、`attemptID?`、`attributionKind?` | 关联曝光及阅读生命周期；点击记为 `same_snapshot`、`after_rerank` 或 `unattributed`。空曝光表示未匹配，不等于用户未曾看见。 |
| `algorithmRank?`、`confidenceBand?`、`interestMatch?` | `algorithmRank` 统一为快照当时 1 基名次；`interestMatch` 为 `untagged`／`tagged_no_match`／`matched`。不能从 v4 的展示理由反推命中。置信度建议分 `0`、`(0, 0.5)`、`[0.5, 1]` 与 `unknown`。 |
| `rankingVariant`、`experimentID?` | 首期只有 `v4`；试验按实际展示变体写入，不能用当前全局设置补填历史记录，也不更改共享 `policyVersion`。 |
| `result?`、`milestone?`、`articleAdapted?`、`feedbackKind?` | 对应事件专用枚举；`articleAdapted` 记录打开后的辅助信号是否适用，不保存域名、错误正文、网页标题、URL 或兴趣词。 |

本机记录示例（演示用，不是 Agent 输出）：

```jsonl
{"schemaVersion":1,"kind":"qualified_exposure","occurredAt":"2026-11-25T09:00:02Z","diagnosticSessionID":"s1","snapshotID":"batch1","contentKey":"local-a","exposureID":"e1","algorithmRank":3,"confidenceBand":"low","interestMatch":"tagged_no_match","rankingVariant":"v4"}
{"schemaVersion":1,"kind":"click_intent","occurredAt":"2026-11-25T09:00:06Z","diagnosticSessionID":"s1","snapshotID":"batch1","contentKey":"local-a","exposureID":"e1","attemptID":"a1","attributionKind":"same_snapshot","algorithmRank":3,"rankingVariant":"v4"}
{"schemaVersion":1,"kind":"first_open_result","occurredAt":"2026-11-25T09:00:07Z","diagnosticSessionID":"s1","snapshotID":"batch1","contentKey":"local-a","exposureID":"e1","attemptID":"a1","result":"opened","rankingVariant":"v4"}
{"schemaVersion":1,"kind":"read_milestone","occurredAt":"2026-11-25T09:00:33Z","diagnosticSessionID":"s1","snapshotID":"batch1","contentKey":"local-a","exposureID":"e1","attemptID":"a1","milestone":"engaged","articleAdapted":false,"rankingVariant":"v4"}
```

同一曝光有两次点击且都达到 `engaged`，只为曝光转化贡献 **1**；两次点击仍分别贡献 **2** 个尝试。若第二次点击来自新快照，但同会话、同变体、同内容且在时窗内，可继续关联 `e1`，并标成重排后归因。首版不将这种归因解释成旧名次导致了新点击；必要时另算仅同快照的敏感性结果。

### 3.3 存储与开关

- 在「隐私与数据 → 兴趣与推荐」新增「记录推荐诊断」，**默认关闭**。说明数据仅本机用于分析、独立关闭和清空，不影响正常阅读；不要把诊断许可绑定到通用 Agent 开关。
- 诊断数据使用独立的本机存储和白名单类型，建议用户专属目录与文件权限分别为 `0700`、`0600`；不纳入通用导出或同步，不写入普通日志。目标保留上限 **30 天或 1 万条**，先到即裁剪。若截断导致时窗不完整，标记可用区间或返回数据不足，不当作零。清空只删除诊断记录及汇总，不清除用户收藏、屏蔽或兴趣画像。
- 仅当学习处于可用状态、已开启诊断、未暂停／隐私阅读／清空时采集。关闭诊断默认停止写入与访问；已有诊断按上限裁剪，用户可另行清空。设计上不从旧兴趣事件回填，也不访问活 `interest.sqlite` 来生成汇总。
- 写入串行、有界、可批处理，不阻塞刷新、滚动或打开阅读器。存储不可用时展示诊断不可用，不把异常拿去训练，也不影响原推荐。未来实现需实测导出、备份及日志边界；本规格不承诺可抵抗同一 macOS 用户下所有本地程序。

## 4. 统计口径

| 指标 | 分子 / 分母 | 使用规则 |
|---|---|---|
| 主指标：每百曝光达到阅读参与门槛的次数 | `100 × 产生至少一次 engaged 的合格曝光ID数 / 合格曝光ID数` | 同一次曝光只算一次。`engaged` 是活跃时长代理，不等于读完或理解；要求已加载且归因成立，沿用读者计时的前台、可见、未锁屏和空闲过滤。 |
| 合格曝光点击转化 | `产生至少一次归因点击的曝光ID数 / 合格曝光ID数` | 不是全站 CTR，也不把未合格卡片计进分母。 |
| 点击归因覆盖率 | `匹配同会话合格曝光的点击尝试数 / 全部合规记录的点击尝试数` | 总览区分同快照和重排后匹配；若覆盖或重排占比变化，不能直接把差值归因于排序。 |
| 打开结果及打开后阅读 | `特定首次结果 / 全部点击尝试`；`达到 engaged 的尝试 / 成功打开尝试` | 失败、阻断、加载前关闭、未结算单列。`qualified`／`deep` 只在可适配样本内报告，分母单列已适配打开次数，同时报告适配覆盖率，避免将非适配站点算作零深读。 |
| 负反馈及覆盖护栏 | `带明确负反馈的归因曝光 / 合格曝光`；前 10 名独立来源数、同源集中度 | 聚合来源分布，不对外返回来源名或 ID；撤销单列，原反馈规则继续按现有语义生效。 |
| 时延护栏 | 同候选规模下排序耗时 P95；分开观测打开失败率 | 排序、刷新与阅读加载分别看；有可靠样本前不设伪精确结论。 |

**统计分母。** 曝光指标按曝光发生日形成队列，点击结果指标按点击发生日形成队列。先等匹配与阅读观察窗收敛，再定稿最近完整本地日；按上述默认最多预留一小时，不把未到观察期限算成无阅读。去重按 ID，不按事件行数。未归因尝试仍进入打开质量和覆盖率，不进入曝光转化。缺记录或被裁剪不等于零分母。

## 5. Agent 只读访问契约

### 5.1 通道、授权与撤权

**建议入口** `newsbarctl recommend summary --window 7d --json`（拟新增，非现有命令）。保持现有 CLI 入口及其他命令行为；推荐诊断使用运行中 App 的独立本机请求—响应通道。实施前只验证一个最小 IPC 路径：同一登录用户、无网络监听、无通用队列写入、有限时和大小限制。若无法满足验收，先只交付 App 内汇总，不退回明文落盘。App 未运行时返回不可用，不自动唤起、不写命令等待下次执行。

| 状态／动作 | 采集 | 推荐 Agent 读取 |
|---|---|---|
| 学习可用，诊断关 | 原学习继续，新增诊断停止 | 拒绝 |
| 诊断开，推荐访问未授予 | 仅本机诊断 | 拒绝；总 Agent 开关开也不够 |
| 总 Agent 开且用户主动授权 | 仅本机诊断 | 仅用户选定日期范围内的固定汇总；建议一次 **15 分钟**，界面显示范围、剩余时间和撤权入口 |
| 授权到期或手动撤权 | 不因仅撤 Agent 权限而停采 | 不接受下一次请求；作废尚未交付的响应 |
| App 退出 | 无采集 | 授权失效，未完成请求不排队 |
| 学习关闭／暂停／隐私阅读／清空 | 停止新增诊断，废弃未刷缓冲 | 拒绝并终止当前授权；恢复学习后不会自动恢复 Agent 权限 |
| 存储不可用或异常重启 | 不影响原排序与阅读 | 不返回上次缓存结果；明确不可用，重启后重新授权 |

请求入口和交付前都检查授权与许可代次，撤权与交付的顺序必须可验证；响应一旦已经交付，就不能承诺收回 Agent 的副本。应用不把响应写到 `outbox`、日志、临时共享文件或崩溃诊断；**App 不自动上传，授权给 Agent 不等于控制 Agent 之后如何使用它。** 审计仅记命令类别、时间和状态，不保存负载。无排序写入、运行期调参或设置接口。

**授权时长与数据跨度分开。** 用户在 App 中确认后，授予的是「允许在 15 分钟内读取这批数据」，不是「只读取过去 15 分钟」或「允许读取全部留存」。默认候选是最近完整 **7 天**，可显式切到 **30 天**；确认前展示准确起止日及缺失天数，授权绑定具体日期、窗口和聚合快照。CLI 不能扩大范围，重新开启诊断不自动恢复旧授权；重新授予历史窗口需要重新确认。允许明确选择历史窗口是为了能分析已有诊断数据，不采用「只读授权后新事件」这种与完整日聚合冲突的口径。

### 5.2 请求与响应

| 项目 | 规格 |
|---|---|
| 请求参数 | 仅 `7d` 或 `30d`，且必须等于本次授权选定的窗口；可选一个预定义视图：总览、算法名次、置信度或标签命中。不支持日期任意截取、任意过滤、交叉维度、逐条轨迹或数据导出文件。 |
| 名次桶 | `1–5`、`6–10`、`11–20`、`21+`；不称为首屏、可见槽位或视觉位置。 |
| 响应字段 | 版本、窗口、`availableFromDay`／`completeThroughDay`、覆盖完整性、可见的聚合计数及分母、定义版本、试验变体（仅有试验时）。使用授权固定的汇总，不通过命令参数切出更小分组。 |
| 小样本 | 建议一个披露分组至少有 **20 条合格曝光**。若总体与其他分组相减可推出被隐藏的小组，进一步合并或隐藏该视图；对同一批数据的反复请求不产生逐次变化的细分结果。固定窗口重叠的差分风险要在端到端测试中覆盖，不能保证时宁可只返回总览或不披露。该门槛不是匿名性保证。 |
| 禁出字段 | 标题、URL、正文、兴趣词、来源名、内容／曝光／点击／阅读标识、逐条时间与分数轨迹。 |
| 结果状态 | `ok`、`insufficient_data`、`not_authorized`、`app_unavailable`、`storage_unavailable`、`invalid_request`、`rate_limited`、`request_timed_out`。请求超时与拒绝都不得回落到活库或旧结果。 |
| 限制 | 短授权、固定时间窗、固定视图与请求限速独立生效。默认建议单请求 3 秒、每授权会话每分钟 10 次；这些是验收前可调整的初始规格，不是当前行为。 |

## 6. 排序候选、证据门槛与回退

1. **固定基线。** 用合成候选覆盖「无标签／有标签未命中／已命中」，其余变量保持相同。记录兴趣项是否可用、原始评分与多样性后名次，写明当前分母差异以及 `unknown` 的行为。已读、显式负反馈和硬屏蔽与主题命中不是一回事。
2. **单一候选。** v4 为 A；候选 B 只令 `tagged_no_match` 不因空兴趣得分扩大个人分归一化分母，其余权重、命中阈值、置信度混合、硬屏蔽、惩罚、公共槽位选择规则、事件去重和 `unknown` 规则不变。实现时用显式的评分变体，缺省始终是 A；B 不将零命中兴趣项计入参与归一化的项，同时保留独立的 `tagged_no_match` 诊断标签，不让 trace 的贡献和与实际得分脱节。
3. **影子排序。** 对同一份不可变的候选、时间、画像和种子并行比较 A/B。记录 Top-10 重叠、名次变化、来源集中度、规则违规数和耗时，不换用户看到的列表、不保存候选标题。先在合成数据与同意使用诊断的本机运行；无法复原旧候选时不声称完成离线回放。影子结果不能估计新顺序的阅读收益。
4. **可选小范围试验。** 只有归因稳定、样本量足、护栏可测才进入。先限定在「为你推荐」，按预先分配的时间块选择 A/B，同块不随刷新跳组，不把旧曝光串到新变体。对照组与试验组共同使用原学习规则；记录时段和画像变化带来的潜在延续效应，只作单机内部决策，不做群体外推。明确开始和结束条件，不靠每天多看一次结果提前停止。
5. **上线判定。** 先用 v4 收集基线、估算能观察到的最小提升和簇内相关；具体样本量和时长在 B4 开始前预注册，**本规格不在没有基线时声称一个样本量就足够**。主指标改善且达到预注册门槛，同时归因覆盖率不过度下滑、来源覆盖和负反馈不退化、耗时达标，才考虑默认使用 B。任一硬约束不满足，立即回 v4；样本不足为「未证实」。
6. **作用域与回退。** 按下表显式隔离变体，不修改全局 `policyVersion` 或 AI 简报缓存键，因为简报输入不变。「将 B 设为默认」只指 Dashboard 展示默认；同时更新该页的排序解释和 trace 标识。若未来要把 B 扩到其他消费者，需另审缓存身份、版本和文案迁移。停排序试验、停诊断、撤 Agent 权限分别生效；无需回滚旧数据或删除画像即可回到 v4。

| 当前 `rank` 调用点 | 本规格选择 |
|---|---|
| `InterestController.rebuild` 的 Dashboard 展示 | 实验关闭时 A；影子运行 A 和 B 但只展示 A；试验打开时按时间块选择，独立标识实际展示变体 |
| `InterestConsumerPolicies` 的研究素材选择、通知摘要选择 | 两处都固定 A |
| `ResearchCandidateBuilder` 深研候选 | 固定 A |
| `SummaryManifest` AI 简报条目选择 | 固定 A，`generationIdentity`、缓存命中及选择不受 Dashboard 试验影响 |

## 7. 工程工作包与验收

| 工作包 | 交付边界 | 放行条件 |
|---|---|---|
| B1 · 基线 | 现有引擎、归因测试和固定合成样例；不采个人行为 | 已有 v4 约束有验证入口，新规则只看单一假设 |
| B2a · 诊断 | 推荐卡片、阅读路由、生命周期的窄触发点；独立采集、设置、存储与 App 内摘要 | C01–C06；启用诊断前后同一行为的 v4 排序及画像保持一致 |
| B2b · Agent | 固定汇总 DTO、本机通道、授权状态、CLI | C07–C10；不能证明无落盘或撤权有效时，不开放该出口 |
| B3 · 影子排序 | v4 与候选的同输入比较，只记录诊断汇总 | C11 通过；不宣称阅读效果 |
| B4 · 可选试验 | 仅展示路径，预先定样本和停止条件，可单独关闭 | C11–C12；试验无足够证据则 v4 保持默认 |

| ID | 验收用例 | 预期 |
|---|---|---|
| C01 | 诊断关闭、学习暂停、隐私阅读、清空中；恢复后旧缓冲到达 | 不新增诊断，不回填旧记录；一般阅读和原设置语义不变。 |
| C02 | 门槛前移出、后台／锁屏／遮挡、滚动来回、重绘与刷新 | 只有合格曝光；同会话重复内容只计一次。 |
| C03 | 跨日常开；诊断跨会话；重排点击、快速点击 | 同会话同变体重排仍可关联原曝光且单列；跨会话、跨变体、快速点击未达门槛不误配。 |
| C04 | WebKit 双失败回调、阻断、加载前关闭、成功后短读、App 退出 | 每个尝试最多一个首次结果；未结算单列；放弃与短读不混淆。 |
| C05 | 同一内容多尝试、无适配器阅读、适配阅读升级深读、打开其他 URL | 活跃时间达标的非适配站点可贡献主指标；适配限定指标分母独立；转化按曝光去重，跳走后的浏览不挂原卡片。 |
| C06 | 旧兴趣数据、诊断容量上限、数据截断、存储不可用 | 无需迁移兴趣库；诊断故障不影响排序；部分窗口不假报整窗为零。 |
| C07 | 总 Agent 开但未授权；授权到期、撤权、暂停、清空和重启；CLI 试图从 7 天切到 30 天 | 无授权或超范围均拒绝；待响应作废；不会自动续期或越过所确认的数据跨度。 |
| C08 | App 未运行、CLI 超时、并发撤权、非法窗口／视图和限流 | 不排队、不自启、不读库；无诊断负载落盘，状态可区分。 |
| C09 | 结构化输出、少量样本、重叠窗口、不同视图互减 | 字段白名单；不能可靠隐藏的小组不披露；已交付数据的边界有文案。 |
| C10 | 关闭 Agent 后继续使用推荐；关闭诊断后继续学习 | 三个开关独立；既有 CLI 命令和行为不受影响。 |
| C11 | 三态合成样本、贡献求和、硬屏蔽、公共槽、事件去重、耗时与共享消费者 | B 只改变所声明的评分环节；通知、两处研究候选和简报仍走 A，简报缓存键和输入选择不变，解释与显示变体一致。 |
| C12 | 试验块刷新、跨组迟到事件、护栏退化、样本不足 | 变体与曝光一致；跨组不误配；随时回 v4，不把无证据报成提升。 |
