# 阶段 2：筛选、核验与研究进展

## 目标与现状

按 v1 方案把新增候选分为「确定性快讯」与「值得深研」两路。现有入口是 `NewsOrchestrator.handleAutomaticResearch`；它以推荐分、兴趣和热度构造候选，随后逐小时调用 `ResearchTriage`，最后通过 `ResearchPipeline` 研究。研究管线已有逐字引文校验、claim 核验、运行阶段/调用计数和旧报告保留。当前缺少公共影响优先级、快讯输出，以及自动搜索的统一日上限。

## 实施顺序

1. 收紧候选池：沿用本轮已到达的热榜及已启用 RSS 增量；先排除屏蔽、过期、重复 URL/转载与近期已处理事件。公共影响和一手新发布优先，明确的本机兴趣作为第二路；两路重复只保留一项。只用标题/主体相似产生待核查候选，不单独证明同一事件。
2. 先做确定性核验：从已取到的文章元信息、启用 RSS 缓存和阶段 4 的官方目录提取来源身份、发布时间及原始字段。公告只证明“机构发布了公告”及其原文字段；实施结果、外界影响、推断范围另找依据。无新鲜可定位来源或存在冲突时只留事件记录，不生成事实型快讯。
3. 分开投递路径：字段和版本对照能回答事实问题时产出 `ResearchQuickFinding`，转为带原始 URL、发布时间和明确 claim 状态的 `NewsEventEvidence` 交给现有 `NewsEventController.ingest`；通知是否投递由事件策略决定。只有影响/兴趣成立、出现实质新事实或证据冲突且存在可回答缺口时才交给研究 Agent。候选筛选器先压低弱候选，再由已有 triage 评估。
4. 加自动搜索日预算：复用 `ResearchLedger` 与 `SearchAttemptTicket` 在每次真实 provider dispatch 前占用额度；缓存命中和跳过 provider 不计数。默认均衡档 20 次/日，可选择 8/20/40；先按快讯补证 8、深研 8、突发 4 作为软分配，单类额度用尽后可从总额度剩余量调剂。该数字只是本机匿名搜索调用上限，不是金额上限。自动研究只用免 Key 通道；配置了 Key 的服务仍只供用户手动研究，除非以后接入可计算的余额、价格、手动保留额及费用硬限。逐 provider 的本地匿名配额中一半保留给手动查询，每任务硬上限继续生效。
5. 保持阅读进展持久化：复用 `ResearchRun.phase`、planned/completed query、pages、AI/search counters 以及 `ResearchRecord.report`。增加可选 `progressFacts` 快照，只在完整正文已本地读取、原句匹配正文，或 validator 支持主张且引用仍匹配正文时分别记录来源、原句、主张；三类均带可打开的来源 URL。新一轮开始清除上一轮快照。运行中的新进度由 coordinator 保存，UI 无需另建侧缓存；报告失败时保留上版。
6. 控制自动深研频率：普通日最多以 3 项为自动日常目标（若用户设置的全局日任务上限更低，则以较低者为准），普通候选保留原每小时频控；只对两小时内新出现的高公共影响事件、重大进展或核心纠错，允许突破自动日常目标最多两项，并且两小时内必须是不同事件。该例外不突破用户设定的全局任务上限、AI/搜索预算或单个任务硬上限；用户没有把任务上限设到 3 以上时，不会出现额外自动研究。
7. 将研究工作台默认筛选改为「待跟进」：重大进展、实质纠错、仍在深研和用户明确关注优先；维持显式排序控件，保留「全部线索」与归档一键入口。没有符合对象时显示简洁空态和全部线索入口，不因此启动联网或研究任务。

## 边界与接口

- `ResearchQuickFinding` 表达事件键、主张、原始来源 URL/标题/发布时间、检查时间和核验状态；只供事件证据/通知候选使用，不把临时计数写入搜索索引。
- 快讯转换为 `NewsEventEvidence` 后走 `NewsEventController.ingest`，官方原始字段资格必须保留来源身份和原始字段；普通 RSS 标题、来源个数或域名数不升级为已核验。
- 阶段 4 的公共资料目录只为当前候选提供证据，不更改订阅；深研及其进度继续归 `ResearchCoordinator` 和 `ResearchStore`。
- 「待跟进」是工作台默认筛选，不会隐藏全部线索或归档，也不改变用户手动选择的排序。待跟进优先级只基于已存事件、更新状态、运行状态和关注状态。
- 不改系统通知路由、静音、预览、投递状态或既有类别；交由通知阶段。

## 验收关注点

- 公共要闻不因低兴趣或低热度自动被漏掉；兴趣研究遵守本机学习和研究开关。
- 同源转载和重复 URL 不重复快讯或研究；不完整/冲突证据仍为待核验。
- 自动 provider 请求在每日日额度前被拦截；搜索故障、限流与人工研究不能绕过已有配额。
- 阅读页读取已有持久化阶段/计数；不增加额外模型调用或阅读路径联网。
