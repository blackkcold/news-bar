# 阅读器受信任代理（旁路由 Fake-IP）

默认严格模式继续拒绝解析到保留/私网地址的网页。旁路由 Fake-IP 网络可手动选择阅读器专用的 HTTP CONNECT 代理；不会修改 macOS 系统代理、网关、DNS 或 Nikki，不影响 AI 提供商请求。

## 使用
1. 打开「设置 → 通用 → 阅读器代理与 Fake-IP 兼容」。
2. 选择「受信任 HTTP CONNECT 代理」。按本次审计报告，入口为 `192.168.0.14`，端口 `7890`，账号 `nikki`。自行输入代理口令，不要把口令发到聊天、截图或日志中。
3. 阅读风险提示并勾选确认，点击「保存并授权本次网络」。账号密码进入应用独立的本机加密账户，不保存到普通偏好或日志。当前加密存储继承项目的机器绑定/同 UID 威胁模型，并非系统 Keychain 级隔离。
4. 点击「测试连接」。只访问 Apple 的 HTTPS 连通性页面，不调用 AI、不自动跳转。成功不代表验证了出口地区或最终目标 IP。
5. 重新打开新闻文章。密码留空可以复用相同地址、端口和账号的已存凭据。

网络路径更新、睡眠或应用重启后，需重新勾选并授权。正在打开的阅读器会停止并释放 WebView，不自动转为严格/透明连接。切回严格模式后也应重新打开文章。

## 安全边界
- 只有阅读器的临时网站数据存储配置代理，禁止非代理 failover。
- 只接受明确的 LAN IPv4 或本机回环作为代理入口，不将其变成可浏览地址白名单。
- 网页仍限 HTTPS；内网字面地址、本地域名、用户信息、非 443 端口、下载及脚本弹窗等原有限制保留。
- 代理模式把目标 DNS/转发判断交给受信任代理。应用无法证明代理实际连接的最终 IP，也不声称通用 WebKit 子资源防火墙。
- WebKit 对回环目标存在独立于 failover 的内置绕过；阅读器必须同时使用 URL 检查和资源阻断规则，不依靠代理配置单独保护内网。
- `7890` 是无 TLS 的 HTTP 代理入口；代理认证口令在局域网链路上不由 TLS 保护，仅在可信家庭网络使用。HTTPS 网站内容仍由浏览器正常验证证书；不会信任任意证书。
- 路由器端的认证、私网目标隔离和出口分流属于独立配置。本次不修改，也不能由一次网页连接成功推断安全或新加坡出口保证。

## 验证范围
受控真实 WebKit 已验证域名 CONNECT 和代理认证头，代理拒绝正确显示失败；严格策略和授权撤销有自动测试。真实 `192.168.0.14:7890` 的认证、Apple 连通性及爱范儿页面仍需用户自行输入口令后验收，本次未读取或尝试猜测路由口令。
