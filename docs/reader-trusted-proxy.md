# 阅读器自动网络与受信任代理（旁路由 Fake-IP）

默认的「自动跟随系统网络」会让阅读器继续使用系统 DNS 与默认网关，并自动识别本地旁路由的 Fake-IP。识别成功时只放行 RFC 2544 的 `198.18.0.0/15`；真实私网、回环、链路本地和 CGNAT 仍然拦截。无需填写代理地址或账号。

## 自动模式（默认）

1. 打开「设置 → 高级 → 阅读器代理与 Fake-IP 兼容」，选择「自动跟随系统网络（推荐）」。
2. 阅读器在启动、换网、睡眠唤醒后，用 `example.com`、`www.cloudflare.com`、`www.apple.com` 三个公网样例和系统默认网关做探测。至少两个样例只返回 `198.18.0.0/15`，且网关是私网地址时，才判定为本地 Fake-IP 网络。
3. 打开文章时自动检测；高级页显示网关、样例解析结果和检测状态，可点「重新检测」。
4. 如需恢复旧行为，打开「严格阻止 Fake-IP（不推荐）」。开启后，Fake-IP 目标继续按内网拦截。
5. 自动模式不修改 macOS 系统代理、网关、DNS 或软路由，不写入任何代理账号或口令。

## 受信任 HTTP CONNECT 代理（可选）

旁路由不提供透明代理、或需要显式指定出口时，可手动选择阅读器专用的 HTTP CONNECT 代理：

1. 选择「受信任 HTTP CONNECT 代理」。
2. 入口使用局域网 IPv4 或 `127.0.0.1`，端口 1–65535。
3. 阅读风险提示并勾选确认，点击「保存并授权本次网络」。账号密码进入应用独立的本机加密账户，不保存到普通偏好或日志。
4. 点击「测试连接」。只访问 Apple 的 HTTPS 连通性页面，不调用 AI、不自动跳转。成功不代表验证了出口地区或最终目标 IP。
5. 重新打开新闻文章。密码留空可以复用相同地址、端口和账号的已存凭据。

网络路径更新、睡眠或应用重启后，需重新勾选并授权。正在打开的阅读器会停止并释放 WebView，不自动转为自动/透明连接。

## 安全边界

- 自动模式只放宽 `198.18.0.0/15`。`10/8`、`172.16/12`、`192.168/16`、`127/8`、`169.254/16`、`100.64/10` 仍然拦截。
- Fake-IP 与真实私网混合的解析结果仍然拦截；单个 Fake-IP 结果、公网网关或不足两个样例都不会触发自动放行。
- 网页仍限 HTTPS；内网字面地址、本地域名、用户信息、非 443 端口、下载及脚本弹窗等原有限制保留。
- WebKit 仍会正常校验证书；自动模式不信任任意证书。
- 受信任代理模式把目标 DNS/转发判断交给代理。应用无法证明代理实际连接的最终 IP，也不声称通用 WebKit 子资源防火墙。
- `7890` 是无 TLS 的 HTTP 代理入口；代理认证口令在局域网链路上不由 TLS 保护，仅在可信家庭网络使用。
- 路由器端的认证、私网目标隔离和出口分流属于独立配置。自动模式不修改这些配置，也不能由一次网页连接成功推断安全或出口地区。

## 验证范围

自动模式有离线单元测试覆盖：Fake-IP 分类、私网网关、样例数量不足、混合私网、网络变化清空缓存、严格 opt-out 和阅读器拦截路径。`NEWSBAR_VALIDATE_FAKE_IP=1` 可运行本机实时探测测试；`NEWSBAR_VALIDATE_FAKE_IP_READER=1` 可运行真实 WebKit 的微博页面验收（两者默认跳过）。
