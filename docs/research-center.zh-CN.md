# 研究中心

研究中心把话题变成一份可核查的报告：规划查询、联网搜索、读取页面、抽取证据、综合成稿，并在标记「已完成」之前逐字校验每条引文。

## 入口

- 菜单栏 Popover：研究 chip 打开最近一条未读报告。
- Dashboard：研究分区列出最近记录；新闻行右键可直接「联网核查」。
- 阅读器工具栏：「联网核查」对当前文章发起研究。
- 设置 → 研究：provider、预算、保留策略与 Firecrawl Key。

## 管线

1. **规划** —— 模型按深度档提出若干查询。
2. **搜索** —— Tavily、Firecrawl、Brave 按故障转移顺序尝试；关闭的 provider 不会被请求。每个任务最多分发 12 次搜索 HTTP。每次分发前先占用一个名额；缓存命中、被跳过的 provider 与冷却均不计数。成功、失败或分发后取消，都按同一实际分发数结算。
3. **读取** —— 内联内容 → 页面缓存 → Firecrawl 抓取（仅在启用且有 Key 时）→ 本地直抓。直抓拒绝非公网 IPv4/IPv6，逐跳校验重定向，响应体流式上限 4 MB。
4. **抽取** —— 模型返回 claim、引文与立场；引文会与已抓取正文逐字比对。
5. **综合** —— 生成 JSON 报告；JSON 非法时最多修复一次。
6. **校验** —— 只有该 claim 自己引用、且引文校验通过的证据才能支撑它；否则保持 `unverified`。

搜索、页面或预算中途失效时，运行会产出 `partial` 报告，而不是直接失败。

## 数据

- `records/<id>.json` 是权威数据；`index.json` 是可重建的投影。
- 运行进度与报告共用一条记录。进度写限速 1 次/秒，索引最多 10 秒刷新一次。
- 删除记录会写入墓碑，迟到的进度回调无法把它复活。
- 默认保留 30 天 / 200 条（可配置）；置顶、在跑、损坏与更高版本记录豁免。
- 记录、索引、meta、缓存、账本与清除意图文件在写入内容**之前**就以 0600 创建（同目录临时文件 + 原子 rename）。写入失败保留原文件。翻译缓存、AI 摘要缓存、API Key 存储、机器 UUID、阅读历史与请求预算文件也使用同一套 0600 写入。
- 记录与索引写入都带 `schemaVersion: 1`。缺版本按 v1 读取；更高版本只做只读投影，旧版本永不覆盖。损坏、不可读或更高版本的记录不能置顶、标记已读或改写，但仍可删除。
- 账本带版本，状态为 `available / corrupt / ioUnavailable / unsupportedVersion`。除 `available` 外一律 fail-closed，界面显示「—」而不是假的 0。重置会先把损坏文件以 0600 归档；有研究任务运行时拒绝重置；也不会恢复任何服务商远端额度。

## Provider 与 Key

密钥只存应用的本机加密文件（AES-GCM、机器绑定），不写 `UserDefaults`，不进日志。Keychain 仅用于旧版一次性迁移。

设置页会显示每家的状态：已关闭、缺少 Key、尚未尝试、上次成功、鉴权被拒、访问被拒、冷却中、上次临时失败。只有确实发送过 Key 的 401 才会被记住；无 Key 的 401 不会造成永久阻断。403 在同一轮研究内不再尝试，但不跨轮记忆。402/429 保留 15/30 分钟冷却。「重试鉴权」只解除该家的鉴权阻断：不发送请求、不解除冷却、不重置账本。保存或清除 Key 会刷新状态，但不会解除额度冷却。

Firecrawl 是唯一还能读取页面的 provider。填入个人 Key 后使用你自己的 Firecrawl 额度；每次研究有页数上限。Firecrawl 关闭或未配置 Key 时，应用**不会**发出任何 Firecrawl 请求，直接回退本地直抓。允许全部 provider 关闭：此时报告降级为 AI-only，并标注「未联网」。

## 自动化

- `researchAutoEnabled` 是爆款与关键词研究的唯一总开关。
- `burstPushEnabled` 只决定报告完成后是否发通知。
- 关键词监控还需要 `keywordTrackingEnabled`。

## 清除历史

所有「清除研究历史」入口共用一个分阶段流程：先写持久化清除意图，停止新研究，写入迁移完成标记，清空搜索快照与页面缓存，删除权威记录，清空旧研究 artifacts（通知去重集合、其他兴趣数据、密钥与账本保留），逐阶段验证，最后移除意图。崩溃或重启会从意图继续，不会把已丢弃的 artifacts 再导入。任一阶段失败都会保留意图并如实报告，不显示「全部清除成功」。旧数据迁移以 artifact 键派生稳定身份（包括归一化为空标题的情况），只有在每条都确认已持久化或可证明等价时才写入一次性完成标记。

这是逻辑清除：不承诺对 SQLite 空闲页、WAL、系统备份或同步副本做取证级擦除。

## 通知

报告完成后只发一条通知：标题「研究完成」，副标题为话题，正文为不超过 80 字的一句话摘要（剥离标记与链接）。失败与取消不推送。点击打开报告；记录已删除时打开列表。

## 隐私

外部流量只会发往已启用的搜索 provider、Firecrawl（启用且有 Key 时）、配置的 AI 端点，以及待核查的页面。同意文案列出实际接收方。通知正文会在锁屏可见，因此做了截断与脱敏。

## 已知限制

- DNS 重绑定已通过连接前解析与校验收窄，但 URLSession 连接时会再次解析；完整的 IP 钉扎仍需自定义连接层。
- Firecrawl 抓取计入你自己的额度；设置页会显示每次研究的页数上限。
- 损坏记录会被隔离，可在数据设置中删除。
