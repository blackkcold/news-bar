# 研究工作台

研究工作台把「主题」「事件」「证据」「研究报告」放在同一条主线里。原来的「研究中心」与「事件监测」两个窗口已合并到这一个窗口；旧入口、旧通知和旧记录仍然可用。

## 入口

- 菜单栏 Popover：研究 chip 打开最近一条未读报告对应的主题。
- Dashboard：研究分区与新闻行「联网核查」都打开同一个工作台。
- 阅读器工具栏与 ⌘K：⌘K 的本地结果包含主题、报告、证据和历史问答；网页搜索仍是显式动作。
- 设置 → 新闻事件：「打开研究工作台」打开统一窗口，并优先选择最近的事件主题。
- 旧的研究/事件通知点击：仍按 `recordID` / `eventID` 定位；新增的 `subjectID` 让点击直接落到对应主题。旧 payload 找不到主题时会先做一次本地关联，不会打开空白窗口。

## 一个主题的日常

- **新建主题**：只建立本地主题，不启动 AI、不抓网页。可选起始链接只作为首次研究的种子，永远不会自动成为证据。
- **关注**：关注后，普通 RSS 刷新若发现匹配主题标题/别名的新条目，会把它收集为「待核查资料」。不会额外联网、不会新建定时器，也不会自动开始 AI 研究。
- **检查更新**：只检查设置中**已启用**的 RSS 源，不调用搜索或 AI。默认一次只检查 1 个源（上限 8，避免一次点掉整个滚动小时预算）；刚完成的共享检查会被复用。304 也算检查成功。
- **预算与退避**：检查与事件追踪共用同一个滚动小时预算和单飞槽。失败会按 5/10/20/40/60 分钟退避；退避不会因为再次点击而被绕过。检查结果会显示实际覆盖的源、预算用量和下次可检查时间。
- **研究**：手动研究、爆款自动研究、关键词研究都经过同一个启动器与配额闸门。手动运行保留完成通知；自动运行是否通知由「研究完成通知」开关决定。
- **版本**：每次成功替换报告都会归档一个版本；失败或部分成功不会伪造新版本。归档旧报告失败时保留旧报告，并把本次运行标为失败。
- **归档**：归档后停止收集新线索和新通知，旧证据、旧报告与历史版本全部保留；取消归档后恢复收集。归档不会删除任何研究记录或事件证据。

## 自动关联与“不自动 AI”

- 新的研究记录和事件会在本地按显式 ID、规范化标题/别名和报告证据 URL 关联到主题。两个同主体但不同时间的事件不会仅因标题相同而合并。
- 事件出现比已就绪报告更新的证据时，主题标为「待核查」；这只是提示，不会自动启动研究。
- 关注主题在既有 RSS 刷新成功时收集线索；不会为了收集线索发起额外请求。
- **监测本身永远不启动 AI、搜索或网页抓取。** 只有用户显式点击「开始研究 / 更新研究 / 联网核查」，或用户已开启的爆款/关键词自动研究规则命中时，才会运行研究管线。

## 通知

- 事件进展优先。同一主题、同一次更新在 30 分钟内不会同时收到事件进展和研究完成两条通知；研究结果仍会显示在工作台。
- 不再对同一种通知做 6 小时一刀切压制：真正的新进展、更正或用户显式发起的新研究仍会通知。
- 同一版报告不会重复通知。事件通知的语义去重键只有在工作台允许投递后才会写入，避免“工作台拒发但事件键被消耗”导致后续真实进展丢失。
- 归档主题不发送新通知，并会说明原因；旧证据保留。取消归档后，新进展会继续提示。
- 通知 payload 继续保留 `type`、`recordID`、`eventID`；`subjectID` 只是新增字段。通知正文仍会在锁屏可见，因此只放任务完成提示，不复制报告结论。

## 迁移

- 不需要迁移文件：旧 `ResearchRecord`、`NewsEvent`、索引与事件快照继续按原格式读取。工作台索引是独立、可重建的层。
- 旧记录/事件首次打开或首次触发本地关联时会自动获得主题；不会改写原记录文件。
- 旧「研究中心」「事件监测」视图仍保留编译，但不再是窗口入口；所有入口都落到 `openResearchWorkspace`。
- 旧的 `research` / `newsEvent` / `burst` 通知点击仍按原键路由，并优先使用新增的 `subjectID`。

## 管线与数据

1. 规划查询 → 2. 多 provider 搜索（禁用 provider 不请求，单任务最多 12 次分发）→ 3. 读取页面（内联/缓存/Firecrawl/本地直抓，拒绝私网与超限响应）→ 4. 抽取 claim、引文与立场 → 5. 综合 JSON 报告 → 6. 逐字校验引文并校验 claim。
2. 只有被 claim 自己引用且逐字校验通过的证据才能支撑它；否则保持 `unverified`。部分失败仍产出 `partial`，不伪装成完整成功。
3. `records/<id>.json` 是权威数据，`index.json` 是可重建投影；工作台索引、报告版本和分析状态另存于 `Research/workspace/`。
4. 记录、索引、缓存、账本与清除意图使用 0600 原子写；更高版本或损坏文件只读隔离，不会被旧版本覆盖。
5. 「清除研究历史」仍走同一分阶段流程：持久化意图 → 停止研究 → 清缓存 → 删记录 → 清工作台版本/分析状态 → 验证 → 移除意图。事件证据保留。

## 隐私与已知限制

- 外部流量只发往已启用的搜索 provider、Firecrawl（启用且有 Key）、配置的 AI 端点和用户显式核查的公开页面。RSS 检查只请求已启用的 RSS 地址。
- DNS 重绑定已通过连接前解析与校验收窄，但系统连接时会再次解析；完整 IP 钉扎仍需自定义连接层。
- 工作台首次打开大库时会在主线程重建一次本地搜索索引；后续只在合并通知后更新。
- 未在发布流程中做人工 UI 验收的改动，仍以编译与代码审阅为准；首次运行应重点检查 1040 pt 宽度下的分栏、长报告滚动与通知点击定位。
